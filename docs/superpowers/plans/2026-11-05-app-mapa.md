# App SmartHealth — primeira versão (mapa) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App Expo em `app/` que abre num mapa centrado no GPS do usuário com os pinos das unidades próximas, busca por nome/tipo, painel de detalhe e botão "Como chegar".

**Architecture:** Expo Router com uma única tela (`app/app/index.tsx`). Lógica pura (cliente HTTP, busca, cores, URL de rota, arredondamento de centro) em `app/src/` com testes jest; hooks de dados com TanStack Query; seleção do pino em um store Zustand. O app só conversa com o api-gateway.

**Tech Stack:** Expo (SDK atual do `create-expo-app`), Expo Router, TypeScript, expo-location, react-native-maps, @tanstack/react-query, zustand, jest-expo.

**Spec:** `docs/superpowers/specs/2026-11-05-app-mapa-design.md`

## Global Constraints

- Dependências nativas/Expo sempre via `npx expo install <pacote>` (nunca `npm install` direto), para casar com o SDK.
- No Windows, rode `npx`/`npm` pelo PowerShell (Git Bash falha com "'node' não é reconhecido").
- O app chama apenas o gateway: base em `process.env.EXPO_PUBLIC_API_URL` (ex.: `http://192.168.0.10:3000`). Rotas usadas: `GET /units`, `GET /units/:codigoCnes`.
- Limites da API: `raio_m` ≤ 50000, `limit` ≤ 200. Resposta JSON em snake_case (contrato em `services/cnes-service/src/docs/openapi.ts`).
- Centro de Teresina (fallback sem GPS): `{ lat: -5.0892, lng: -42.8019 }`.
- Fora do escopo: sintomas, login, `expo-secure-store`, área de gestor, site, rota desenhada dentro do app.
- Textos da interface, código e commits em português; conventional commits com escopo `app` (`feat(app): ...`).

## Review Focus

1. Gateway ou cnes-service fora do ar (503 / rede): o mapa continua aberto e mostra aviso "Não foi possível carregar as unidades", sem crash. → teste em Task 2 (`ApiError`) e estado de erro na Task 5.
2. Permissão de localização negada: mapa abre no centro de Teresina e as distâncias são relativas a ele. → Task 4 (`useLocalizacao` usa `TERESINA_CENTRO`).
3. Busca com acento/caixa diferente ("saude", "SAÚDE", "upa"): encontra as mesmas unidades. → teste em Task 3.
4. Busca sem resultado: mensagem "Nenhuma unidade encontrada" em vez de lista vazia muda. → Task 5.
5. Unidade sem telefone/endereço ou não verificada: painel omite os campos `null` e não mostra seção de horários. → Task 5 (`PainelUnidade` só renderiza campos não nulos).

### Task 3: Busca local por nome e tipo

**Files:**
- Create: `app/src/busca/normalizar.ts`, `app/src/busca/sinonimos.ts`, `app/src/busca/filtrar.ts`, `app/test/busca.test.ts`

**Interfaces:**
- Consumes: `Unidade` (Task 2).
- Produces:
  - `normalizarTexto(texto: string): string` — minúsculas, sem acentos (`normalize("NFD")` + remover marcas), espaços colapsados, trim.
  - `SINONIMOS_TIPO: Record<string, number[]>` com exatamente: `upa: [73]`, `pronto atendimento: [73]`, `pronto socorro: [20]`, `emergencia: [20, 73]`, `urgencia: [20, 73]`, `hospital: [5, 7, 15]`, `maternidade: [5, 7]`, `posto: [1, 2]`, `ubs: [1, 2]`, `postinho: [1, 2]`, `policlinica: [4]`. Comentário: é aqui que entra a futura tabela de sintomas (termo → tipos).
  - `filtrarUnidades(unidades: Unidade[], termo: string): Unidade[]` — termo vazio devolve tudo; senão, mantém unidades cujo nome normalizado contém o termo normalizado **ou** cujo `tipo.codigo` está nos tipos de algum sinônimo contido no termo. Preserva a ordem de entrada (já vem por distância da API).

- [ ] **Step 1: Testes que falham** — `test/busca.test.ts` com 3 unidades fictícias (UPA tipo 73 "UNIDADE DE PRONTO ATENDIMENTO SATELITE", UBS tipo 2 "UBS SANTA ISABEL", hospital tipo 5 "HOSPITAL E MATERNIDADE DO SATÉLITE"):
  - `normalizarTexto("  Saúde  PÚBLICA ")` → `"saude publica"`.
  - `"upa"` → só a UPA; `"UPA"` → só a UPA.
  - `"satelite"` → UPA e hospital, nessa ordem.
  - `"posto"` → só a UBS.
  - `"xyz"` → `[]`; `""` → as 3.
- [ ] **Step 2:** `npx jest test/busca.test.ts` → FAIL.
- [ ] **Step 3:** Implementar os três arquivos.
- [ ] **Step 4:** `npx jest` → PASS.

### Task 4: Utilitários do mapa, rota e localização

**Files:**
- Create: `app/src/mapa/cores.ts`, `app/src/mapa/centro.ts`, `app/src/rota/abrirRota.ts`, `app/src/localizacao/useLocalizacao.ts`, `app/test/mapa.test.ts`

**Interfaces:**
- Consumes: `Coordenada`, `TERESINA_CENTRO` (Task 1).
- Produces:
  - `corDoTipo(codigo: number): string` — 73 e 20: `"#d32f2f"`; 5, 7, 15: `"#1565c0"`; 1, 2: `"#2e7d32"`; demais: `"#6d6d6d"`.
  - `arredondarCentro(c: Coordenada): Coordenada` — 3 casas decimais (~100 m), usado na chave da query para não refazer a busca a cada pixel arrastado.
  - `urlRota(destino: Coordenada, plataforma: "ios" | "android" | string): string` — iOS: `http://maps.apple.com/?daddr=LAT,LNG`; outras: `https://www.google.com/maps/dir/?api=1&destination=LAT,LNG`.
  - `abrirRota(destino: Coordenada): Promise<void>` — `Linking.openURL(urlRota(destino, Platform.OS))`.
  - `useLocalizacao(): { posicao: Coordenada; usandoGps: boolean; carregando: boolean }` — pede `requestForegroundPermissionsAsync`; se negada ou erro, `posicao = TERESINA_CENTRO` e `usandoGps = false`.

- [ ] **Step 1: Testes que falham** — `test/mapa.test.ts`:
  - `corDoTipo(73)` → `"#d32f2f"`, `corDoTipo(2)` → `"#2e7d32"`, `corDoTipo(999)` → `"#6d6d6d"`.
  - `arredondarCentro({ lat: -5.08923, lng: -42.80187 })` → `{ lat: -5.089, lng: -42.802 }`.
  - `urlRota({ lat: -5.1, lng: -42.8 }, "ios")` → `"http://maps.apple.com/?daddr=-5.1,-42.8"`; com `"android"` → `"https://www.google.com/maps/dir/?api=1&destination=-5.1,-42.8"`.
- [ ] **Step 2:** `npx jest test/mapa.test.ts` → FAIL.
- [ ] **Step 3:** Implementar os arquivos (o hook não tem teste unitário; é coberto na verificação manual da Task 5).
